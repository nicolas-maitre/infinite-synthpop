# Infinite Synthpop: generator design

**Goal:** a web page that plays an endless stream of generated songs in the style analysed in
[../analysis.md](../analysis.md). It needs full transport and mixer controls, sampled 80s drum
machines with a synthesized fallback, and nothing loaded from a CDN at runtime.

**Status:** v1 implemented. The harmony, form, tempo and bass were revised after measuring the
reference recordings (analysis §1–§3).

## Stack

- **Vite + TypeScript (strict)**, with **Tone.js** bundled from npm. ESLint (typescript-eslint),
  Prettier and Vitest handle quality.
- pnpm (npm 11.4's resolver crashes on vitest 5's peer graph).
- `pnpm fetch-samples` downloads the drum samples once into `public/samples/`. They come from
  `geikha/tidal-drum-machines`, pinned to a commit. The samples are git-ignored because the source
  repo states no license.

## Architecture

The core is pure, deterministic code with no audio: a seed in, a song out. That's what makes it
unit-testable. The audio side only plays events.

```
rng.ts           seeded PRNG (mulberry32)
theory.ts        pitch classes, keys, Roman-numeral chords, scales, voicing
genres.ts        genre profiles: references, tempo, keys, progression bank, every style weighting
progressions.ts  progression picking + style-weighted substitutions (analysis §3)
composer.ts      Song = sections + per-song motifs (riff, melodic bass, melodies)
arranger.ts      (song, bar index) → BarEvents: every note for every track in that bar
───────────────── audio boundary ─────────────────
drums.ts         sample kits (SP-12 / LinnDrum / DMX) + synthesized fallback kit
instruments.ts   synth voices, effects buses, mixer channels
engine.ts        Transport loop: each bar asks the arranger for events and schedules them;
                 chains songs forever
render.ts        offline render to WAV, saved by a dev-only Vite endpoint, for measurement
main.ts          controls, mixer, section timeline, chord display, visualiser
```

### Key decisions

- **Contour motifs.** The riff, melodic bass and arpeggio are stored as _rhythm + contour indices
  into the current chord's tones_. The same motif re-harmonises over every chord, which keeps the
  hook recognisable across the progression.
- **Melodies are 8-bar lines realised once per song per section type**, then repeated. That
  repetition is what makes the output sound like a song instead of noise. Bars 4–7 replay bars
  0–3's rhythm and random choices over their own chords, so the melody follows DS's two-line
  verse, then cadences on the root.
- **The style slider (0 = True Faith, 1 = Different Story)** biases these choices: the chorus's
  Dorian IV vs minor iv, a modal v vs major V, the TF form blocks (VI turnaround, i–IV bass-solo
  vamp, instrumental chorus, modulating outro) vs the DS ones (interlude, ii–IV turnaround, break,
  chorus to fade), and the bounce bass vs the pulse bass.
- **Every style weighting lives in a genre profile** (`src/genres.ts`, `GENRES.synthpop`), which
  composer, progressions, arranger, instruments and wizard read instead of hard-coded numbers. The
  profile holds the genre's references (TF at style 0, DS at 1), tempo range and centre, key
  weights, progression bank and substitutions, kit and bass-figure weights, ending, counter-line
  and section-planner odds, drum details and bass tone. `compose` takes a `genre` (default
  `synthpop`) and the song records it; specs and share links don't carry it yet. `style` becomes
  one weight per reference (`[1 − style, style]`), and each style-dependent number is a `Blend`:
  a base plus what each reference adds in proportion to its weight (`0.1 + 0.7 × TF`). That's the
  form the old expressions had, so the output stayed bit-identical (checked by
  `src/snapshot.test.ts`), and it extends to 3+ references once the weights come from a point in
  a polygon instead of the slider. Drum details (TF's intro low tom and beat-3 open hat, DS's
  extra kick and tambourine) are per-reference traits that apply while that reference outweighs
  every other; on a tie, the genre's defaults.
- **The mix is matched by measurement.** `scripts/compare_mix.py` compares loudness, crest factor,
  stereo width and band energy with the recordings. That's how two bugs were found: Tone.Channel
  defaults to mono, which collapsed the stereo field, and the bass sat too low and thin. A third
  hid in the bus EQ: a Tone.EQ3-style band split (2nd-order bands summed) notched the mix by 20–25
  dB near 120 Hz and 3.3 kHz, so it is now two shelves and a gain, flat when all gains are 0.
- **UI timing uses timers, not Tone.Draw.** Draw rides requestAnimationFrame and drops callbacks
  more than 0.25 s late, so the display froze in background tabs.
- **Gated reverb** is built from a reverb return whose gain is opened and closed on each
  snare/clap hit. That's the 80s gate, keyed to the drum hit.
- **Infinite play.** When a song ends, the engine composes the next one from the next seed. The
  key, the tempo (116–121 BPM, centred on 118.5 between the measured 117.0 and 119.8, unless locked) and the drum kit (when set to "Auto") change
  between songs.

## Controls

Play/stop · new song · skip section · seed (replays any song) · tempo with an auto/lock switch ·
key (auto or fixed) · drum kit · Faith ↔ Story slider · per-track volume / mute / solo · master
volume.

## Out of scope for v1

An audio-export button in the UI (the renderer exists; only dev tooling uses it) · MIDI out ·
real vocals or lyrics.
