# Playback / DJ view

The page today is one view with every control: generator, style pad, mixer, creator, exports,
originals, playback internals. That stays, as the **advanced** view. Next to it, a **simple**
view that works like an enhanced music player: what's playing, what played, your favourites, the
originals, and a few plain choices about what comes next.

## Decisions

- **Two views, one page, one engine.** A Simple | Advanced switch in the header. Switching never
  stops or changes the music. The choice is remembered (`prefs.view`).
- **Simple opens first, for everyone**, new visitors and existing users alike, until they switch.
- **DJ is on by default.** New visitors get `dj: true`. Existing users have `dj: false` saved
  (every pref change writes the whole object), so it is turned on once, with the first switch to
  the simple view as the default (`prefs.djDefaulted`); after that their own choice holds.
- **Next and Mix next are two buttons.** Next cuts to a new song at once, as a music player
  does. Mix next (DJ on) starts a DJ transition into the next song at the next phrase line.
- **Previous** goes back through the songs that played (restarting the current one first when
  it has played more than 3 s, as players do). Next after Previous walks forward through that
  history before it generates new songs.
- **The included library is the 10 Originals.**
- **The length range drives both** the composed length of generated songs and, in DJ mode, how
  long each song plays before it mixes out.
- **The mixer stays reachable**: a volume slider with an arrow that opens the full mixer under it.

On a phone the three lists become tabs under the player.

### Now playing

- Title, the genre / key / tempo line, the DJ mix line (`renderMix`), and the buffer status.
- The visualiser, smaller. A second `Visualizer` on its own canvas, reading the same analysers;
  only the visible view's one draws.
- ♡ saves to favourites (the same `library.save` as the advanced ♥ Save), ⤴ copies the link.

### Transport

| Control    | Does                                                                                     |
| ---------- | ---------------------------------------------------------------------------------------- |
| ⏮ Previous | Restarts the song if past 3 s, else plays the previous song in the history, at once      |
| ▶ / ❚❚     | Play / pause (today's toggle)                                                            |
| ⏭ Next     | The next song in the history if you went back, else a new random one, at once            |
| ⇢ Mix next | DJ on only: mixes into the next song from the next phrase line (see engine work)         |
| Seek bar   | Elapsed / total; drag or click to jump (bar-quantised, `jumpTo`). Shows the mix-out mark |
| 🔁 Repeat  | Off / this song. On: the song plays to its end and starts again; the DJ doesn't mix out  |

The section-level controls (skip section, loop section) stay advanced-only. Keyboard: Space
play/pause, ←/→ previous/next, M mix next, R repeat. The media session's next/previous follow
the same buttons (today previous only restarts the song).

### Volume and mixer

A master volume slider (the same `prefs.master`) with a ▸ arrow. The arrow opens a drawer, and
the drawer holds the advanced view's mixer card itself: the node moves between views, so there is
one set of faders and no state to keep in sync.

### Switches

- **DJ**: the existing `prefs.dj` (with its Transition style left to the advanced view, on auto).
  Disabled with its tooltip where the browser can't render ahead.
- **Lite playback**: lite vs auto of the existing Performance setting. It reloads the page, as
  today; the switch says so.

### What plays next

- **Genre**: Any (auto) / Synthpop / Italo / Euro disco. It sets `prefs.genre` with the style on
  auto. If the advanced view has an open blend or a fixed style point, the select shows
  "Custom (advanced)" until a genre is picked here.
- **Length**: a two-handle range, 2–6 min in 30 s steps, default 2:30–5:00.

### Lists

- **Previous songs**: newest first, the last 50, kept across visits. Each row: title, genre /
  key / tempo, when; click plays it again (exactly: seed and spec, as a saved song), ♡ saves it.
- **Favourites**: the existing library (My songs), same rows and actions as the advanced card
  (play, share, delete with undo).
- **Originals**: the 10 reference songs, playing through `engine.playReference` as the buttons
  do now.

## How it's built

- **`src/prefs.ts`**: `Prefs`, `loadPrefs`, `savePrefs` moved out of `main.ts` (1700 lines), plus
  `view`, `djDefaulted`, `repeat`, `length: { min, max }`.
- **`src/history.ts`**: like `library.ts`. Records a song when it starts being heard (the
  engine's `onSong`, which DJ mode already fires at audio time), not when it's composed. Stores
  `{ seed, spec }` for generated songs and the id for originals, capped at 50, plus a cursor for
  Previous / Next. Tested on its own (`history.test.ts`).
- **`src/simpleview.ts`**: `mountSimpleView(root, api)`, in the style of `mountCreator` and
  `mountWizard`. `main.ts` hands it an API (play, next, previous, mixNext, seek, setRepeat, setDj,
  setGenre, setLength, setLite, play saved / original / history entry) and calls its `render*`
  hooks from the existing engine events.
- **`index.html` / `style.css`**: the simple view's markup in its own `<main>`, the switch in
  the header, `body[data-view="simple" | "advanced"]` hiding the other one.

### Engine work

1. **Instant next.** `newSong(seed, { instant: true })` (and the same for `playCustom` /
   `playReference`), whatever the Switch setting says: the simple view's buttons cut at once.
2. **Mix next.** `engine.mixSoon()` re-plans the DJ swap bar to the next 8-bar phrase line that
   render ahead can still reach (a few seconds on, as other changes in render ahead), and keeps
   the crossfade's 16-bar mix-in intro short enough to fit (8 bars, kick-less half dropped).
   The mix line shows it at once ("Mixing next → …").
3. **Repeat.** `engine.setRepeat(on)`: at the song's end, bar 0 of the same song; the DJ plans no
   mix-out while it's on.
4. **Length range.** `EngineSettings.length: { min, max }` in seconds.
   - Composing: the form (short / standard / long, as the Create dialog picks) whose length at
     the song's tempo fits the range best.
   - DJ (`swapBar`): the earliest bar is at least `min`; options past `max` are dropped, unless
     none is left, then the one nearest `max`. Tested in `dj.test.ts`.
5. **Mix-out bar for the seek bar.** `engine.mixOutBar`: the planned swap, or null.

## Phases

1. **Shell.** `prefs.ts`, the view switch, the simple layout: now playing, play / pause, instant
   Next, seek bar, Repeat, DJ (on by default), Lite, volume with the mixer drawer, Genre. **Done.**
   - Until phase 2, Previous goes back to the start of the song.
   - Next (button, → and N, the media keys) cuts at once in the simple view; in the advanced view
     N and the media keys still follow the Switch setting.
   - Repeat sits right of Next, as in most players.
   - A `#song=` creation link opens the advanced view for that visit (creator mode lives there),
     without changing the remembered view.
2. **History.** `history.ts`, Previous, the Previous songs list; Favourites and Originals lists.
   **Done.**
   - The three lists are tabs in one card, on every screen size (three columns were too narrow
     at the view's width).
   - A song from the lists (and a favourite) plays again as it was, once, through
     `Engine.replaySong`; the songs then go on from it. In the advanced view, My songs still
     opens a song as a creation, which loops.
   - Previous goes back a song within its first 2 bars (about 4 s), else restarts it.
   - In the advanced view, N and Random song stay a new random song; the media keys walk the
     history in both views.
3. **Mix next.**
4. **Length range.** Composer and `swapBar`.

Each phase is checked in Chromium and Firefox (headless), audio muted.
